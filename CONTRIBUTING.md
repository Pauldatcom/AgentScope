# Contributing

Contributions are welcome and appreciated. This document covers the workflow
for submitting changes, adding new data sources, and adding new AI providers.

## Workflow

1. **Fork** the repository and create a feature branch:
   ```bash
   git checkout -b feat/your-feature-name
   ```
2. **Make your changes** following the code style (enforced by `ruff`).
3. **Run tests locally**:
   ```bash
   make test       # unit + e2e
   make lint       # ruff
   make typecheck   # mypy
   ```
4. **Open a pull request** against `main`. Link the issue it closes and
   fill out the PR checklist.
5. **Address review feedback** — at least one approving review is required.
6. **Squash-merge** is preferred.

## Branch naming

| Type | Pattern | Example |
|---|---|---|
| Feature | `feat/<short-description>` | `feat/import-pipeline` |
| Fix | `fix/<short-description>` | `fix/dedup-key-collision` |
| Docs | `docs/<short-description>` | `docs/update-readme` |
| Chore | `chore/<short-description>` | `chore/update-deps` |

## Commit style

Conventional Commits:

```
feat: add CSV reader support
fix: prevent duplicate sessions on re-import
docs: update indicator definitions
test: add normalizer edge case tests
chore: bump SQLAlchemy to 2.0.52
```

Reference the issue number in the body: `Closes #42`.

## Code style

- **Python**: formatted by `ruff` (line length 100, target `py312`).
- **TypeScript**: strict mode, no unused locals/params.
- **Imports**: sorted by `ruff` (`isort` rules).

## Running tests

```bash
# Unit + e2e (no Postgres, no network required)
make test

# Integration (requires PostgreSQL via Docker)
make test-integration

# Lint + type check
make lint
make typecheck
```

## Adding a new data source

No code changes are needed — the import engine is driven by configuration:

1. Import the file via `POST /imports/upload` or the UI assistant.
2. If the structure is unknown, use the AI assistant (`/assistant` page) to
   propose a mapping. Edit, preview, and validate.
3. The mapping is saved in the `mapping` table (versioned and reusable).
4. Document the mapping in `docs/mappings.md`.

See `.github/ISSUE_TEMPLATE/data_source.md` for the template to propose a new
source.

## Adding a new AI provider

1. Implement `MappingAgentPort` in `agentscope/adapters/ia/<provider>/`.
2. Wire it in `agentscope/api/main.py::_build_mapping_agent`.
3. Add the provider to `.env.example` and `docs/ai_providers.md`.
4. No changes to `domain` or `application` are required.

## AI usage policy

- AI assistance for development is expected; you remain responsible for
  correctness.
- Never commit secrets or API keys.
- Never execute code generated by an AI model at import time — mappings are
  applied by the deterministic engine only (see `docs/decisions.md`, ADR-002).
- The AI proposes; the engine applies.
